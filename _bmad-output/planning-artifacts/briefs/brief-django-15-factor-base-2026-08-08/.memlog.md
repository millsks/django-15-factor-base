- (decision) FIVE MORE OPEN ITEMS CLOSED before the PRD handoff. (3) HEALTH SIGNAL: two asymmetric endpoints - liveness answers 'is the process alive' and touches NOTHING external, readiness answers 'can it serve now' and checks the database. Rationale: a liveness probe that queries the DB turns a brief DB outage into a crash loop across every replica simultaneously; readiness failing is recoverable. REFINED the selected option: readiness deliberately does NOT re-check migrations, because the startup refusal already answered that permanently, re-asking costs a query per probe, and during a rolling deploy an older replica legitimately runs against a newer schema. Readiness is also the shutdown signal, flipping unready on SIGTERM before the drain. (5)+(4) DEV KEYPAIR AND PERSONAS: keypair generated on demand into a gitignored path, never committed - a committed key in a TEMPLATE would ship inside every component ever generated from it. Personas declared as configuration and materialised by a seeding task, with one persona in the is_staff-driving group, replacing createsuperuser locally; several personas with differing groups are the point, since a single superuser cannot exercise the mapper's authorization differences. (6) REFUSAL LIST settled at SIX conditions, TWO OF THEM CONDITIONAL: sqlite / local credentials / unapplied migrations / OTEL_SDK_DISABLED always; LocMemCache only where Redis was selected and CELERY_TASK_ALWAYS_EAGER only where background tasks were selected. The conditionality is required, not cosmetic - production.py:32-43 hardcodes Redis, so the generator strips it from a no-Redis component and Django's default LocMemCache legitimately applies, meaning an unconditional refusal would reject 4 of the 12 valid combinations.
