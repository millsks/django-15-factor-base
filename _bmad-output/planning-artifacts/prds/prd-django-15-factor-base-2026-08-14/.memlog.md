- (override) NARROWS FR-9. 'On every authentication the mapper resolves, adds, removes, sets staff status' is unimplementable as written for the programmatic flow, where DRF authenticates every request: read literally it mandates a group diff and up to two M2M writes per API call for one identity. Architecture splits the mapper into RESOLVE (every authentication, indexed read) and SYNC (once per credential epoch - every interactive login, once per Bearer token at first sighting of its jti). Consequence to record: for the programmatic flow, a revoked group is honoured until the token expires. Distinct from Open Question 1, which covers sessions only.
